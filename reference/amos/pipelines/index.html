    2. amos

    Named pipelines: an analyst, a critic, and an artist for a kind of study.

    Name a pipeline in the "general" section (or in the project's section), and the settings of the project's analyst, critic, and artist are filled in for you, so a whole study can be a few lines:

    [general]
label = target
seed = 43
pipeline = classification

    Every setting that you write yourself wins, so a pipeline is a starting point: change one setting (such as "model_techniques" in the "analyst" section, or a technique's parameters) and keep the rest. If the project's section does not list its workers, they are the analyst, critic, and artist. A worker's own section can name another pipeline for that worker. The settings are filled in when the project is created, so Project.idea (and the "settings.json" that Project.export saves) has every one of them.

    The steps that depend on the data use the choosers of the auto module, so one pipeline adapts to the data when it is applied: auto_imputer fills missing values (if there are any), auto_encoder encodes each categorical feature by how many levels it has, auto_sampler balances rare classes (if they are rare), auto_model chooses among models whose assumptions the data meets, auto_evaluator applies the evaluators that suit the model, and auto_plot draws the figures that suit it. Each records why it chose what it did in a table of the dataset.

    Pipeline Task For
    classification classify Predicting classes: an experiment that compares logit, random_forest, gradient_boosting, and baseline by balanced accuracy, after balancing rare classes.
    regression regress Predicting a number: an experiment that compares ridge, random_forest, gradient_boosting, and baseline by RMSE.
    count_regression regress Predicting counts: an experiment that compares poisson, negative_binomial, and a random forest and gradient boosting fitted for counts, with baseline, by RMSE.
    classification_inference classify The effects of the features on classes: a logit_sm, mnlogit, or ordinal_regression model (whichever suits the classes), with its coefficients in a regression table.
    regression_inference regress The effects of the features on a number: ols, or robust_regression if the errors have outliers.
    count_inference regress The effects of the features on counts: poisson, negative_binomial (for overdispersed counts), or zero_inflated_poisson (for excess zeros).
    panel_classification classify Panel data of classes: a fixest logit model with the groups as fixed effects, clustered by the first group.
    panel_regression regress Panel data of numbers: a fixest model with the groups as fixed effects, clustered by the first group.

    The pipelines that predict scale the numeric features and resample rare classes, which helps models predict. The pipelines for inference do neither: they keep the coefficients in the units of the features, keep the real share of each class (resampling would distort the coefficients and their standard errors), and encode each categorical feature against a reference level (its first), so its coefficients are differences from that level. The panel pipelines need "groups" in the "general" section.

    Every model also has a pipeline of its own for each task that it can do, named for the model and the task, such as xgboost_classification, xgboost_regression, or ols_regression (for a model whose name ends in "_regression", "_inference" takes its place, as in quantile_inference). fixest has the panel pipelines. Each prepares the data as its model needs, and no more:

    • Features are scaled only for a model that needs it: standardized for a penalized linear model (whose penalty depends on the scale of each feature) and for a support vector machine, nearest neighbors, or a neural network (which measure distances or learn weights), and made more normal for naive Bayes (which assumes that they are). Trees and models for inference are not scaled.
    • Missing values are left for the models that handle them (gradient boosting, LightGBM, XGBoost, CatBoost, explainable boosting, and TabPFN), and filled for the others.
    • Categories are encoded against a reference level for a model with an intercept and no penalty, so that their dummy variables are not collinear.
    • Rare classes are weighted by the models that can weigh them (such as a random forest or a logit model), resampled for those that cannot (such as nearest neighbors or XGBoost), and kept as they are for models for inference, explainable boosting, and TabPFN.
    • A model that overfits without tuning has a hyperparameter search (scored by balanced accuracy or RMSE), such as a decision tree's depth or the penalty of a lasso. Nearest neighbors keep only the 20 features most related to the label, and a neural network stops early.

    The critic and artist of each apply the evaluators and draw the plots that suit its model's family (with auto_evaluator and auto_plot, which leave out those that do not suit the fitted model, such as SHAP values without shap installed): SHAP values and partial dependence for trees, a regression table and the plots that check a model's assumptions (normal errors, influential rows, calibration) for models for inference, shape functions for explainable boosting, a learning curve for a neural network, and survival curves for a Cox model. Models of groups (gee, mixedlm, and binomial_bayes_mixedglm) need "groups" in the "general" section, and are tested on groups that they have not seen. The cox_regression pipeline needs "event" in the "cox_parameters" section, and wls_regression needs "weights" in the "wls_parameters" section. See the technique catalog for every pipeline.

    def parameters_for(
    self,
    groups: Sequence[str] | str | None) -> dict[str, dict[str, Any]]:
    """Returns the parameters of techniques for a project.

    Args:
        groups: the "groups" of the "general" section of the settings.

    Raises:
        ValueError: if the pipeline uses the groups as fixed effects (or
            its model needs groups) and there are none.

    Returns:
        A copy of `parameters`, with the fixed effects and cluster of
            `fixest` if the pipeline uses the groups as fixed effects.

    """
    parameters = {
        name: dict(copy.deepcopy(values))
        for name, values in self.parameters.items()}
    names = chrisjen.utilities.listify_names(groups)
    if (self.fixed_effects or self.grouped) and not names:
        use = (
            'uses the groups as fixed effects' if self.fixed_effects
            else 'models the rows of each group as correlated')
        message = (
            f'the {self.name!r} pipeline {use}: set "groups" in the '
            f'"general" section'
        )
        raise ValueError(message)
    if self.fixed_effects:
        fixest = parameters.setdefault('fixest', {})
        fixest.setdefault('fixed_effects', names)
        fixest.setdefault('cluster', names[0])
    return parameters

    def expand(idea: MutableMapping[str, Any], name: str | None = None) -> None:
    """Fills in the settings of the pipelines named in `idea`.

    A pipeline named in the "general" section or the project's section fills
    in the analyst, critic, and artist that the project lists (all three, if
    it lists no workers, and a project section is added if there is none). A
    pipeline named in the section of one of those workers fills in that
    worker instead. Every setting already in `idea` is kept, so calling this
    again changes nothing. The "task" of the "general" section is set to the
    task of the pipelines, if it is not set.

    Sections are replaced rather than changed in place, so a section that
    `idea` shares with other settings is not changed.

    Args:
        idea: the settings of a project, which are changed.
        name: the name of the project. Defaults to `None`, in which case it
            is found as `chrisjen` finds it: from the first section whose
            name ends in "_project", or the first other section that is not
            special, a worker's, or parameters.

    Raises:
        ValueError: if a pipeline is not named in `PIPELINES`, is named in
            the section of a worker other than the analyst, critic, or
            artist, is for another task than the "task" of the "general"
            section or the other pipelines named, or uses the groups as
            fixed effects and the "general" section has none.

    """
    general = dict(idea.get('general', {}))
    project = _project_section(idea, name)
    chosen = _named(idea[project], project) if project is not None else None
    chosen = chosen or _named(general, 'general')
    used: dict[str, Pipeline] = {}
    if chosen is not None:
        if project is None:
            project = f'{name or chosen.name}_project'
            idea[project] = {}
        for stage in _workers(idea, project):
            if stage in _STAGES:
                used[stage] = chosen
    for key, section in list(idea.items()):
        if key in {'general', project} or not isinstance(section, Mapping):
            continue
        own = _named(section, key)
        if own is None:
            continue
        if key not in _STAGES:
            message = (
                f'a pipeline is named in the {key!r} section, but only the '
                f'"general" section, the project\'s section, and the '
                f'sections of the {", ".join(_STAGES)} can name one'
            )
            raise ValueError(message)
        used[key] = own
    if not used:
        return
    for stage, pipeline in used.items():
        idea[stage] = {
            **copy.deepcopy(dict(pipeline.stages[stage])),
            **idea.get(stage, {})}
    pipelines = list({p.name: p for p in used.values()}.values())
    for pipeline in pipelines:
        for technique, values in pipeline.parameters_for(
                general.get('groups')).items():
            key = f'{technique}_parameters'
            idea[key] = {**values, **idea.get(key, {})}
        _share_required(idea, pipeline)
    general['task'] = _task_of(pipelines, general.get('task'))
    idea['general'] = general
