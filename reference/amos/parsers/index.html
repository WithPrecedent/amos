    amos.parsers ¶

    Techniques that turn the text in a dataset into data.

    These are techniques of the "wrangler" stage of a project. A loader brings documents into a dataset as they are (load_files makes a row for each file, with its text in a "text" column), and parsers then find information in that text and make columns of it, such as whether a contract can be renewed, the city in an address, or the authors of a paper. Like a munger, a parser keeps the rows and every column. Each search covers every row at once with the vectorized methods of pandas (such as those of Series.str), so parsing is fast even with many documents.

    Each kind of search is a parser of its own, which a workflow can name in its settings with a pattern and the columns to search and make (see PatternParser.parse). Several values in one cell are separated by a comma and a space unless the separator is set:

    Parser Kind Makes
    parse_flags flags True if the pattern appears, and otherwise false.
    parse_counts counts The number of times the pattern appears.
    parse_category category The value if the pattern appears. With several patterns (or rules), the first that matches wins, so they can turn text into categories (such as the name of a state into its abbreviation).
    parse_categories categories The value of every pattern (or rule) that appears, once each, in order. A value cannot have the separator in it.
    parse_match match The first match, or a column for each named group of the pattern (such as "(?P\d{4})"), named for the group after the name if there is one.
    parse_matches matches Every match, or a column for each named group as parse_match makes.
    parse_split split A column for each name: the text before the first match, between the first and second, and so on, with the rest of the text in the last. Text without a match is all in the first.
    parse_names names The names in the text, found by splitting the text wherever the pattern matches. The pattern should match the words and punctuation between names (such as "AUTHORS", "BY", "AND", and commas). The names are made upper-case without periods or apostrophes (so "O'Brien" is "OBRIEN"), line breaks always separate them, and pieces without two letters are left out.
    parse_fields fields A column for each label that the pattern matches (such as "MEDICAL HISTORY:"), with the text after the label, up to the next label. The columns are named for the labels in snake case ("medical_history"), after the name if there is one.
    parse_replace replace The text with every match replaced by the value, which can include the groups of the match ("\1" is the first). A blank value removes the matches. Without a name, the text it searches is changed.

    parse_all applies a rulebook: an ordered list of rules, each of which is one of these searches, named by its kind. Rules are usually rows of CSV files (spreadsheets), so they can be read and changed without knowing Python. They can also be dicts in settings, with the same keys. The columns are:

    Column Meaning
    column The columns of text to search, separated by commas. Defaults to the parser's "column" (such as "text") if blank.
    name The column that the rule makes (or adds to). A split rule names two or more, separated by commas. It is blank for a replace rule that changes the text it searches, and optional for a fields rule (whose columns are named for the labels in the text) and for a match or matches rule whose pattern has named groups.
    kind What the rule does: one of the kinds above, or the kind of a pattern parser of your own.
    pattern A regular expression to search for.
    value What a category, categories, or replace rule writes. Otherwise blank.
    flags Any of "ignorecase", "dotall" (so "." also matches line breaks), "multiline" (so "^" and "$" match at each line), and "verbose", separated by commas. Optional.
    separator What separates several values in one cell, for categories, matches, and names rules. Optional: a comma and a space if blank.
    note Anything you want to say about the rule. It is not used. Optional.

    Rules are applied from top to bottom, and every column that a rule makes can be searched by the rules after it, so a rule can find a section of a document (with match, split, or fields) for later rules to search. Rules that make the same column are combined: flags are true if any rule matches, counts are added, the first category or match that matches is kept, and the results of categories, matches, and names rules are joined. A text that is missing matches nothing. A parser given several patterns combines them in the same way, as rules of the same name.

    The kinds that this module first used (flag, count, map, map_all, extract, and extract_all) are read as the kinds they became. CSV files in an older layout of rules (with "target" for column, "variable" for name, TRUE or FALSE in "ignorecase" and "dotall" columns, and the kinds "label", "labels", "section", "matches", "excerpts", and "remove") are read too, as the rules they stand for.

    To write a parser, subclass Parser and write parse. To write a parser that can also be a kind of rule, subclass PatternParser and write find: the subclass is then a kind of rule, named for the class (ParseInitials is "initials"). To name a rulebook, so that settings and other rulebooks can use it, subclass ParseAll and set its rules (see ParseAll).

    Bases: Parser

    Finds information in text with a rulebook.

    The rules can be the path of a CSV file of rules or of a folder of them, a list of rules (as dicts, with the columns of a CSV file as keys), the name of a rulebook, or a list of any of these, which are applied in order (see Rulebook.create). Each rule is applied by the pattern parser of its kind (see PatternParser).

    A subclass that sets rules is a rulebook of its own. It is in the library under its name, like any technique, so settings can name it as a technique ("parse_federal" for ParseFederal) that needs no parameters. Its name, with or without "parse_", is also the name of its rulebook, which other rulebooks and the "rules" of parse_all can name ("rules = federal"). For example, a package built on amos can keep its rules in its own CSV files:

    The rules are read each time they are used, so changes to their files take effect at once.

def check_value(cls, rule: Rule) -> str:
    """Returns the value of a rule, which cannot have its separator.

    Args:
        rule: the rule, with its value as it was given.

    Raises:
        ValueError: if the value is blank or has the separator in it
            (without the spaces around it, such as a comma).

    Returns:
        The value, as text trimmed of spaces.

    """
    if _is_blank(rule.value):
        message = (
            f'a {cls.kind()} rule needs a value to write when it matches')
        raise ValueError(message)
    text = str(rule.value).strip()
    mark = rule.separator.strip() or rule.separator
    if mark and mark in text:
        message = (
            f'the value {text!r} has {mark!r}, which separates the values '
            f'of {cls.kind()} rules'
        )
        raise ValueError(message)
    return text

    """Adds the rule's value to each row where the pattern appears.

        found[listed] = None
    _add_to(made, name, found, index, rule.separator)

    def find(
    self,
    rule: Rule,
    texts: Mapping[str, pd.Series],
    made: dict[str, pd.Series],
    index: pd.Index) -> None:
    """Makes a column for each label, with the text after it (text).

    Args:
        rule: the search.
        texts: the columns of text to search, by name, in order.
        made: the columns that earlier rules made, by name.
        index: the labels of the rows.

    """
    label = _body(rule.pattern)
    source = _wrap(
        rule.pattern,
        '(?P<_label>',
        f')(?P<_text>(?s:.*?))(?=(?:{label})|\\Z)')
    prefix = f'{rule.names[0]}_' if rule.names else ''
    for text in texts.values():
        plain = text.reset_index(drop = True)
        matches = plain.str.extractall(source, flags = rule.flags)
        if matches.empty:
            continue
        keys = [_field_name(str(k)) for k in matches['_label']]
        table = pd.DataFrame({
            'row': matches.index.get_level_values(0),
            'key': [f'{prefix}{k}' for k in keys],
            'text': _patterns.tidy(
                matches['_text'].astype('str')).to_numpy(dtype = object)})
