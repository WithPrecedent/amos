    Techniques that choose which features a model uses.

    These are techniques of the "analyst" stage, usually in a step of their own (such as "select") after the features are encoded and scaled. Each one keeps some of the features and removes the rest. Most are transformers (see the transformers module), so they learn which features to keep from the training rows only, choose from the numeric and boolean features by default, and can be limited to some columns.

    feature_group instead keeps the features that the settings list, so an experiment can compare groups of features that you chose. Name each group in a "feature_groups" section of the settings, and then name the groups as the techniques of a step:

    [analyst]
steps = split, select, model
select_techniques = demographics, case_facts
model_techniques = logit

[feature_groups]
demographics = age, sex, race
case_facts = court, year, claims

    Features listed as "always_use" in that section are not a group of their own: every group keeps them too, so they are in every group's path.

    Contents

    Selector: genre of techniques that keep some of the features. ExhaustiveSelection: keeps the best of every set of 1 to 3 features. FeatureGroup: keeps the features that the settings list. GenericUnivariate: keeps the features most related to the label, by a mode that the parameters choose. KBest: keeps the k features most related to the label. RecursiveElimination: removes the least important feature of a model, again and again. RecursiveEliminationCV: removes features as recursive_elimination does and keeps the number that scores best. SelectFdr: keeps the features related to the label, controlling the false discovery rate. SelectFpr: keeps the features related to the label, controlling the false positive rate. SelectFromModel: keeps the features that a model finds most important. SelectFwe: keeps the features related to the label, controlling the family-wise error rate. SelectPercentile: keeps a share of the features most related to the label. SequentialSelection: adds (or removes) features with mlxtend while the score improves. SequentialSelectionSK: adds (or removes) features with scikit-learn while the score improves. VarianceThreshold: removes features whose variance is at or below a threshold. register_feature_groups: adds the feature groups of the settings to the library. _ALWAYS: name in the feature groups of the features every group keeps. _GROUP_TECHNIQUE: names of FeatureGroup and its numbered copies. _SECTION: name of the section of the settings with the feature groups.

    FeatureGroup(contents=None, name='', parameters=dict()) dataclass ¶

    Bases: Selector

    Keeps the features that the settings list, and removes the others.

    The features are "columns": by default, those that the "feature_groups" section of the settings lists for the technique's name (see register_feature_groups). If that section lists features as "always_use", a group built for a project keeps them too, whatever its other features are, so every group shares them. A listed name that is not a feature keeps the features made from it by an encoder or other transformer, whose names start with it and an underscore (so "court" keeps "court_federal" and "court_state" after one_hot). The label and groups are not features, so they are always kept and cannot be listed.

    Unlike other selectors, it learns nothing from the data, and it chooses from features of every kind.

    def apply(
    self,
    item: base.Dataset,
    columns: Sequence[str] | str | None = None,
    **kwargs: Any) -> base.Dataset:
    """Keeps the features in `columns`, and removes the others.

    Args:
        item: the dataset to change.
        columns: names of the features to keep. Defaults to `None`, which
            raises an error.
        **kwargs: not used.

    Raises:
        KeyError: if a name in `columns` is not a feature and no feature
            was made from it.
        ValueError: if `columns` is not given.

    Returns:
        The dataset, with only the chosen features.

    """
    if columns is None:
        message = (
            f'{self.name!r} has no features: list them for it in the '
            f'"{_SECTION}" section of the settings, or pass "columns"'
        )
        raise ValueError(message)
    names = [str(c) for c in camina.listify(columns)]
    kept = _match_features(item.features, names)
    missing = [n for n in names if not kept[n]]
    if missing:
        message = (
            f'{self.name!r} lists {missing}, which are not features of '
            f'the data (the label and groups are not features)'
        )
        raise KeyError(message)
    chosen = {f for found in kept.values() for f in found}
    removed = [c for c in item.features if c not in chosen]
    item.update_features(removed, pd.DataFrame(index = item.data.index))
    # A group is often only in a project's own library, so it records its
    # genre for the scorecard (which looks names up in chrisjen.library).
    item.record(
        self.name,
        genre = 'selector',
        listed = names,
        kept = [c for c in item.features if c in chosen],
        removed = removed)
    return item

    @classmethod
def build(
    cls,
    name: str,
    project: chrisjen.Project,
    parameters: base.GenericDict | None = None,
    **kwargs: Any) -> FeatureGroup:
    """Builds the technique, with the features of its group.

    Args:
        name: name of the technique, which is the name of its group in
            the "feature_groups" section of the settings, if it has one.
        project: the project the technique belongs to.
        parameters: more parameters, which take precedence over those in
            the settings. Defaults to `None`.
        **kwargs: other arguments for the constructor.

    Returns:
        The built technique.

    """
    technique = cast('FeatureGroup', super().build(
        name, project, parameters = parameters, **kwargs))
    groups = project.idea.get(_SECTION, {})
    if name in groups and name != _ALWAYS:
        technique.parameters.setdefault('columns', groups[name])
    columns = technique.parameters.get('columns')
    if columns is not None and _ALWAYS in groups:
        listed = [str(c) for c in camina.listify(columns)]
        always = [str(c) for c in camina.listify(groups[_ALWAYS])]
        technique.parameters['columns'] = [
            *listed, *(c for c in always if c not in listed)]
    return technique

    Keeps the features most related to the label, by a mode it is given.

    "mode" is "percentile" (the default), "k_best", "fpr", "fdr", or "fwe", and "param" is the setting of that mode (50 by default, so it keeps half of the features).     def apply(
    self,
    item: base.Dataset,
    columns: Sequence[str] | None = None,
    **kwargs: Any) -> base.Dataset:
    """Keeps the best number of features, and adds the score of each.

    Args:
        item: the dataset to transform.
        columns: names of the columns to choose from. Defaults to `None`,
            which uses `select`.
        **kwargs: parameters for the selector.

    Returns:
        The transformed dataset, with the table of the search.

    """
    super().apply(item, columns = columns, **kwargs)
    tool = item.fitted.get(self.name)
    if tool is not None:
        results = tool.cv_results_
        item.tables[f'{self.name}_search'] = pd.DataFrame({
            'size': np.asarray(results['n_features'], dtype = int),
            'score': np.asarray(results['mean_test_score'], dtype = float),
            'std': np.asarray(results['std_test_score'], dtype = float),
            }).sort_values(
                'score', ascending = False, kind = 'stable',
                ignore_index = True)
    return item

    Adds (or removes) features one at a time while the score improves.

    mlxtend's sequential search starts with no features and adds the one that most improves the score of the model, again and again (or, if "forward" is false, starts with every feature and removes them).     SequentialSelectionSK(contents='sklearn.feature_selection.SequentialFeatureSelector', name='', parameters=dict()) dataclass ¶

    Bases: _ModelSearch, Selector

    Adds (or removes) features one at a time until it keeps enough.

    scikit-learn's sequential search adds the feature that most improves the score of the model, again and again (or, if "direction" is "backward", removes the feature whose removal least lowers it). It keeps n_features_to_select features, or by default ("auto") half of them, or if "tol" is set, stops when the score improves by less than "tol". See _ModelBased and _ModelSearch for the model, score, and folds. Unlike sequential_selection, it needs no optional package, but it does not report the score of each set.

    def register_feature_groups(
    idea: MutableMapping[str, Any],
    library: chrisjen.Library | None = None) -> None:
    """Adds the feature groups of the settings to the library.

    Each name in the "feature_groups" section of the settings is stored in the
    library as `FeatureGroup`, so it can be named as a technique (usually of a
    step such as "select"), and that technique keeps the features listed for
    it. The `Project` calls this when it builds its workflow. "always_use" is
    not a group: its features are kept by every group (see `FeatureGroup`),
    so it is checked but not added.

    Groups can also be listed in the parameters of `feature_group` (or of a
    numbered copy, such as `feature_group2`), as in a "feature_group_parameters"
    section with "raw = a, b" and "refined = c, d". Each step that names that
    technique then names each of its groups in its place, so an experiment
    compares them as branches, and the groups are added to the
    "feature_groups" section. "always_use" in those parameters is kept by
    each of those groups.

    Args:
        idea: the settings of a project.
        library: the library to add the groups to. Defaults to `None`, which
            uses `chrisjen.library`.

    Raises:
        TypeError: if the "feature_groups" section is not a section, or a
            group is not a name or a list of names.
        ValueError: if a group lists no features, has the name of another
            class in the library, or is listed with other features in two
            places.

    """
    library = chrisjen.library if library is None else library
    _expand_parameter_groups(idea)
    if _SECTION not in idea:
        return
    groups = idea[_SECTION]
    if not isinstance(groups, Mapping):
        message = (
            f'the "{_SECTION}" settings must be a section that names each '
            f'group, not {groups!r}'
        )
        raise TypeError(message)
    for name, columns in groups.items():
        if not isinstance(columns, str | Sequence) or not all(
            isinstance(c, str) for c in camina.listify(columns)):
            message = (
                f'the feature group {name!r} must be a column name or a list '
                f'of them, not {columns!r}'
            )
            raise TypeError(message)
        if not camina.listify(columns):
            message = f'the feature group {name!r} lists no features'
            raise ValueError(message)
        if name == _ALWAYS:
            continue
        existing = library.all.get(name)
        if existing is FeatureGroup:
            continue
        if existing is not None:
            message = (
                f'the feature group {name!r} has the name of the '
                f'{existing.__name__} class in the library: name it something '
                f'else'
            )
            raise ValueError(message)
        library.add(FeatureGroup, name = name)
